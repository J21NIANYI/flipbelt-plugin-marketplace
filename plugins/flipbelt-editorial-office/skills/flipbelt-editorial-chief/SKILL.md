# 飞比特知识库编辑部

## 开始
读取 [工作区与共同约束](references/workspace-contract.md) 和 [任务路由](references/routing.md)。执行任何领域工作前读取目标编辑 Skill；这表示加载工作指引，不是调用独立运行时。规则或依赖不可读时停止该路径，不能靠记忆恢复。
单一明确任务直接进入所属编辑，不必生成完整项目。混合任务按对象拆分，先目标知识、后源页面引用。

## 编排
1. 定位真实 Page/Entity/Section，记录用户目标、允许的来源、影响范围；先查相关对象，不默认全库扫描。
2. 按路由表确定编辑和 L1–L4；事实风险与改动大小分开判断。
3. L2–L4 使用 [内部任务记录](references/job-template.md)，锁定文件哈希、基线和每个对象的唯一写作者。用户已有未提交修改属于基线的一部分。
4. 涉及引用或新实体时先读 [关系台](../flipbelt-reference-desk/SKILL.md)。缺目标仅登记候选；显式创建扩展知识才进入研究。
5. 各编辑逐文档写作并自查；完成后按 [审校](../flipbelt-editorial-review/SKILL.md) 进行独立复核。
6. [交付](../flipbelt-editorial-delivery/SKILL.md) 汇总实际成果与待办。不得由 Chief 把未执行动作声明为完成。

## 编辑会
用户明确要求编辑会、知识缺口或扫描时，界定其主题/目录范围，读取真实对象和 Tracking，列选题、证据、依赖与优先级。已有但无入链仅是观察，不自动判低质量；不因提出选题而创建正文或维护全库。
动态文章、HTML 制作、编辑、上传或发布需求按 [动态 HTML 契约](references/dynamic-html.md) 路由；采用现有 V2 Page 展示层，不新建类型。平台未部署时可完成本地制品，线上路径据实际能力停止。

## 本地统一入口
涉及本地编辑、检查或 Revision 交付时，读取 [fbkb 操作契约](references/knowledge-operations.md)；遵循本职责的自动检查与授权边界。
