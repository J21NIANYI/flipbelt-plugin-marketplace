# 专栏流程
专栏回答为什么值得关注、如何理解或应用，百科定义通过已有 Reference 衔接。没有最低篇幅或固定章节数。
有原稿时逐段建立“原观点/事实→保留或调整→来源→理由”映射，以原稿为正文主稿，不自动浓缩为概要。保留被支持的论点和具体信息，不为格式改造丢失内容。
新稿先建立中心问题、已有知识清单与证据，再形成叙述。已有知识不能支撑的新外部事实按 [研究规则](../../flipbelt-extended-editor/references/source-policy.md) 当次核验。
产品事实来自当前受控知识和本次允许资料，不从公开品牌宣称推导产品性能。引用产品应用前读取完整相关 Product Page，记录基线；若任务使用线上 release，示例锁同版，不混拼本地/线上不同版本。
事实、推论和观点区分表达；条件写在相关句子附近，不设置重复宣传边界板块。通用概念不大段复制百科，缺实体也不自行创建 extended。
现有 kb_column_source_audit.py 有历史 V1 映射依赖，仅在匹配的历史来源核对中用，不作为新专栏通用门禁；原稿始终只读。
默认交付 V2 column；不生成游戏、视频、图像或新格式。
