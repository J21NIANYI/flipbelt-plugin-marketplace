# 审校流程
输入包括用户范围、基线、目标对象、差异、来源和实际工具结果；关键输入不足为 BLOCKED。
审校先核事实适用范围，再看结构/引用和表达。写作者自查是准备，不代替独立审校；独立 Agent 的建议不等于人工业务验收。
FACT/SOURCE 错误、引用断链、Schema 不通过、敏感信息泄露为 NEEDS_REVISION；基线冲突、缺来源/依赖为 BLOCKED。
非阻断候选仅 WARNING；不为消除 Warning 自动写新词条。内容 pending 不必一律阻断：按 Schema 发布资格及读者是否被误导判断，明确局部限制。
最终状态与审校的文件哈希绑定；文件变化须重新核对。对未覆盖维度写 NOT_CHECKED 而非 PASS；未独立复核写待复核。
T0 纯文案/注释/Skill 路由检查 diff；T1 小范围低风险执行最相关检查；T2 内容/关系/数据处理执行定向与核心路径；T3 Schema/权限/删除/兼容/发布另加充分兼容与恢复验证。
仓库明确要求 V2 Schema、Audit、Preview 和定向测试时遵从；不要用 T0 省掉实际 V2 内容变更的仓库门禁。通过后无新证据不重复扩大检查。
